## Review before implementation

The frozen source already prohibited fabricated Building/Blueprint filesystem packages, but the live A06 failure showed the rule was not operational enough: a response could present a concrete storage-derived install tree and only later refuse the ZIP.

The remediation was therefore limited to:

1. an explicit Building/Blueprint package hard stop in the public SIM runtime;
2. the same hard stop in the editor-native owner;
3. the same rule in canonical K11 knowledge;
4. exact generated COPY/reference hash updates;
5. a behavioral regression reproducing the concrete-tree-before-refusal failure.

The generated `production/sim/references/editor-content.md` was not treated as an independent source of truth; canonical K11 was changed and the COPY reference/source-map hash was regenerated consistently.

## Remediation behavior

The remediated runtime now makes the Building/Blueprint package boundary explicit:

- if loader/install semantics are unverified, stop before showing concrete filesystem structure;
- do not enumerate `Software Inc\Buildings\...`, `Software Inc\Blueprints\...`, `Buildings/*.build`, or `Blueprints/*.xml` as an install/delivery tree;
- path/extension evidence may only be described as storage/export observations with explicit separation from installation semantics;
- no tree diagram, package skeleton, path mapping, install recipe, installer, or ZIP may be synthesized from those observations;
- return `TOOLING_BLOCKED` when supported native authoring/export is unavailable;
- a later refusal does not cure an earlier forbidden concrete-tree claim.

Behavioral regression:

`A06-BHV-10 — Concrete Building Blueprint install tree before later refusal`
