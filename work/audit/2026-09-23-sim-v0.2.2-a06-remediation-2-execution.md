## Failure motivating this cycle

The second live A06 response correctly returned `TOOLING_BLOCKED` and refused the final ZIP, but still violated the remediated contract by:

1. asserting loader-style semantics that files "load as" specific Building/Blueprint storage paths/extensions before the final refusal;
2. rendering a concrete rejected/negative-example `Mods/MyBuilding/...` package tree.

The first remediation therefore activated too late in the reasoning flow.

## Remediation design

The Building/Blueprint package guard was moved to a **P0 preflight before any web search, repository search, personal-context lookup, source browsing, path reasoning, or artifact generation**.

When the request asks for exact folders/install paths/package trees/installers/ZIPs while loader/install semantics are not already verified, the runtime must:

- stop before path/extension research;
- not search for or repeat filesystem paths, filenames, extension-to-directory mappings, loader locations, or storage directory names;
- not show negative/rejected/hypothetical example trees;
- not state that assets "load as", "go in", "belong in", or install at a particular path from storage/export observations;
- return the bounded result:
  `TOOLING_BLOCKED — native Building/Blueprint authoring/export evidence required.`
- state only that current canonical evidence does not establish standalone loader/install semantics and that a real native export/artifact or supported native authoring/export surface is required;
- then stop.

Behavioral regression:
`A06-BHV-11 — P0 preflight blocks loader claim and negative example tree`
