# SIM v0.2.2 Plan B — Artifact and Security Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the confirmed artifact-integrity and untrusted-input gaps: symlink escape, unbounded archive expansion, weak legacy per-file verification, raw/private payload policy, and over-broad package-validation claims.

**Architecture:** Add one versioned archive-safety policy, enforce workspace-safe traversal in builders, make archive inspection budget-aware, strengthen the legacy v0.1 verifier to check declared file hashes against actual ZIP entries, and make package validators report their real coverage ceiling. Security checks fail closed and remain deterministic.

**Tech Stack:** Python 3, pytest, zipfile, pathlib, JSON, existing repository verification tooling.

**Spec:** `docs/superpowers/specs/2026-09-22-sim-v0.2.2-integrity-plugin-architecture-design.md`

## Global Constraints

- User-provided files and archives are untrusted data.
- No builder follows symlinks, junctions/reparse points where detectable, or special files.
- No archive member may escape the declared workspace after path normalization.
- Archive limits are sourced from `production/sim/manifests/archive-safety-policy.json`.
- Limit breaches return deterministic blocked/error states; they never silently truncate and continue as PASS.
- Windows-target case-insensitive path collisions are treated as ambiguous/unsafe.
- Legacy v0.1 verifier hardening does not imply the published v0.1.0 bundle is known corrupted.
- Raw game binaries/private capture payloads remain forbidden in committed public corpus paths.
- Package validators must advertise their actual family coverage.
- No production code is written before its owning test has failed for the expected reason.
- Every task runs focused tests, then full `python -m pytest -v` before commit.
- No marketplace publication, live acceptance, merge, or release is part of this plan.

## Review Focus

1. **Symlink-to-outside file:** packaging must reject rather than archive external bytes.
2. **ZIP bomb:** highly compressible input that exceeds ratio or total expansion must block before materializing all bytes.
3. **Case-insensitive duplicate paths:** `Data/Game.tyd` and `data/game.tyd` must be rejected for Windows-target packaging/intake.
4. **Manifest/report tampering:** changing packed knowledge bytes and recomputing only the outer bundle hash must still fail legacy verification.
5. **Unsupported package family:** generic validator must return an explicit unsupported/partial result, never imply full validation.

## Plan B Completion Criteria

Plan B is complete only when:

- mod ZIP building cannot read outside the declared workspace through symlinks;
- ZIP output is reproducible independent of source mtimes;
- archive intake has explicit entry/size/ratio/depth/cumulative limits;
- Windows-target normalized/casefold duplicate paths fail closed;
- legacy release verifier detects packed-file tampering even when outer hashes are updated;
- repository verification rejects governed raw/private game evidence in public corpus paths;
- package validators state their real coverage ceiling;
- full repository suite is green.

Plan B does not create the plugin projection or execute live A01–A12.
