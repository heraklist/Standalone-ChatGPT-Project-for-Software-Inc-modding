# SIM v0.2.2 Plan A — Integrity Contracts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make SIM acceptance, release state, collision classification, and artifact-state advancement mechanically evidence-bound before plugin packaging or live certification consumes those contracts.

**Architecture:** Introduce one transport-neutral certification context, one candidate-bound acceptance aggregator, one canonical collision-index schema, and one machine-readable finalization policy. Existing release/build code becomes a consumer of these contracts rather than independently deriving status. Historical v0.2.0/v0.2.1 live evidence remains readable as history but cannot certify a v0.2.2 candidate.

**Tech Stack:** Python 3, pytest, JSON Schema Draft 2020-12, deterministic JSON, existing SIM repository tools.

**Spec:** `docs/superpowers/specs/2026-09-22-sim-v0.2.2-integrity-plugin-architecture-design.md`

## Global Constraints

- Canonical Software Inc target remains exactly `Beta 1.8.42`.
- Exact-target certification context must include SHA-256 of `work/corpus/beta-1.8.42/capture-manifest.json`.
- Machine resolver identity remains `sim`; user-facing display remains `SIM`.
- Historical A01–A06 records are regression history only unless they already contain all required v0.2.2 certification identity fields.
- No A-case from candidate X may contribute to candidate Y.
- Release metadata never overrides recomputed evidence.
- Machine verification IDs are exactly `V0` through `V5`.
- Human display labels remain descriptive metadata only.
- Building/Blueprint fail-closed behavior is unchanged.
- No production code is written before its owning test has been run and observed failing for the expected reason.
- Every task ends with the focused test, then the full `python -m pytest -v` suite before commit.
- Plan A does not bump `production/sim/manifests/sim-manifest.json`; Plan C owns the runtime version transition to `0.2.2-preview`. Plan A acceptance tests may use synthetic `0.2.2-preview` contexts because they validate the future contract, while release-verifier regression tests derive the current built version from the report.
- No merge, release, marketplace publication, or branch deletion is part of this plan.

## Review Focus

1. **Mixed-candidate retest chains:** a later A06 record for another candidate must never supersede the current candidate's A06.
2. **Same bytes / different transport:** marketplace and ZIP transport metadata must not create different behavioral candidates when `candidate_tree_sha256` is identical.
3. **Tampered release status:** editing `release_status`, `surface_acceptance`, or `known_gaps` must fail independent verification.
4. **Collision object schema:** `{"identifier":"Game","occurrences":[...]}` must classify as `VANILLA_COLLISION` end-to-end.
5. **Final artifact at V2:** a static-only family may become `FINAL_ARTIFACT` only when the finalization policy explicitly permits V2 and required static evidence exists.

```python
from __future__ import annotations

import json
from dataclasses import dataclass
from pathlib import Path


ALLOWED_RESULTS = {"PASS", "FAIL", "PLATFORM_LIMITATION", "NOT_TESTED"}


@dataclass(frozen=True)
class CertificationContext:
    candidate_tree_sha256: str
    semantic_aggregate_sha256: str
    source_commit: str
    plugin_version: str
    exact_target_manifest_sha256: str
    protocol_version: str
    surface: str


@dataclass(frozen=True)
class AcceptanceSummary:
    status: str
    case_results: dict[str, str]
    known_gaps: tuple[str, ...]


def load_acceptance_records(evidence_dir: Path) -> list[dict]:
    records: list[dict] = []
    if not evidence_dir.is_dir():
        return records
    for path in sorted(evidence_dir.glob("*.json")):
        data = json.loads(path.read_text(encoding="utf-8"))
        data["_record_id"] = path.stem
        records.append(data)
    return records
```

Implement context matching on all certification fields, build retest parent/child relations only within matched records, require exactly one terminal record per required case, map missing cases to `NOT_TESTED`, and compute status `FAIL` > `INCOMPLETE` > `PASS`.

Ambiguous multiple terminal records must raise `ValueError` rather than choose by filename or timestamp.
