# SIM v0.2.2 Plan C — Deterministic @sim Plugin Projection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and independently validate a reproducible one-public-Skill SIM plugin candidate from the existing `production/sim` authority, without creating a second handwritten runtime source.

**Architecture:** Freeze runtime topology in `production/sim/RUNTIME.json`, define one source-controlled projection policy, read all projected bytes from an explicit Git source commit S, and generate a closed-world plugin candidate in a temporary output directory. The builder records source/projection provenance; an independent validator recomputes expected source bytes and final candidate identity. Actual `plugins/sim` materialization commit P and marketplace registration commit M occur only in Plan D after candidate freeze.

**Tech Stack:** Python 3, Git CLI object access, pytest, JSON, deterministic filesystem output, SHA-256, existing SIM source tree.

**Spec:** `docs/superpowers/specs/2026-09-22-sim-v0.2.2-integrity-plugin-architecture-design.md`

## Global Constraints

- Handwritten runtime authority remains exactly `production/sim`.
- Generated plugin projection is never a second semantic authority.
- Plugin identity is `sim`; display name is `SIM`; machine resolver key is `@sim`.
- Exactly one public Skill exists in the candidate: `skills/sim/SKILL.md`.
- Internal domain/lifecycle `SKILL.md` files become non-public `.md` references.
- Root SIM `SKILL.md` is exact-byte projected; no build-time prose augmentation.
- Candidate source bytes come from exact source commit S, not mutable working-tree content.
- Projection relations are only `EXACT_BYTE_COPY`, `REMAP_EXACT_BYTE_COPY`, `GENERATED_METADATA`, `GENERATED_PROVENANCE`.
- `candidate_tree_sha256` is computed over the final candidate tree and recorded outside candidate bytes.
- No plugin metadata may require an OpenAI API key, API billing, mandatory paid service, undeclared App, or undeclared MCP.
- Generated `plugins/sim` is **not committed in this plan**; Plan D owns materialization P.
- `.agents/plugins/marketplace.json` is **not committed in this plan**; Plan D owns registration M after P exists.
- No production code before a failing test.
- Each task runs focused tests and full `python -m pytest -v` before commit.
- No live A-case execution, merge, or release is part of this plan.

## Review Focus

1. **Dirty worktree:** changing local `production/sim/SKILL.md` after S must not alter candidate built from S.
2. **Second public Skill:** any extra nested `SKILL.md` must fail closed.
3. **Undeclared file:** adding a valid-looking file to candidate must fail independent validation.
4. **Source/projection drift:** changing projected module bytes while rewriting candidate provenance must still fail against Git source S.
5. **Hash recursion:** final candidate tree digest must be stable without being embedded back into the tree it hashes.

## Plan C Completion Criteria

Plan C is complete only when:

- runtime topology and projection policy are machine-readable;
- source bytes come from exact S, not dirty worktree;
- candidate has exactly one public Skill;
- internal modules are non-public exact-byte projections;
- portable and compatibility plugin metadata are generated deterministically;
- final candidate-tree identity is deterministic and recursion-free;
- independent validator catches source/projection/provenance/topology tampering;
- marketplace registration can be rendered for an existing P but is not yet published;
- current upload package no longer semantically augments root Skill;
- CI builds, independently validates, and reproducibility-checks the plugin candidate;
- no generated plugin tree or marketplace pin has yet been committed.

Plan D owns S freeze, P materialization, M registration, installation, live certification, and release audit.
