# SIM v0.2.2 Plan D — Live Certification and Release Governance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Freeze one exact v0.2.2 plugin candidate, materialize and register it through the S→P→M publication sequence, run fresh same-candidate ChatGPT/Codex certification, and produce release-readiness evidence without publishing or merging unless the owner separately authorizes those protected actions.

**Architecture:** Plan D consumes the completed contracts/security/plugin tooling from Plans A–C. It freezes semantic source S, generates the validated plugin tree, commits that generated tree as P, creates marketplace registration M pinning P, proves installation provenance, runs A06 first as the live canary, then completes all fresh required behavioral cases on the same candidate. Certification is reconstructed from evidence, not manually declared.

**Tech Stack:** Git/GitHub, Python 3 verification tools, JSON Schema, ChatGPT plugin/Skill surface, Codex plugin surface, existing SIM acceptance protocol.

**Spec:** `docs/superpowers/specs/2026-09-22-sim-v0.2.2-integrity-plugin-architecture-design.md`

## Global Constraints

- Plan A, B, and C release-blocking prerequisites must be green before certification.
- S is the semantic source freeze.
- P contains the exact generated `plugins/sim` candidate built from S.
- M contains marketplace registration pinning P.
- Candidate behavioral identity is `candidate_tree_sha256`; P/M are provenance, not substitutes.
- Exact target context includes SHA-256 of resolved Beta 1.8.42 capture manifest.
- ChatGPT G5 requires fresh A01–A12 on one exact candidate/context.
- A06 executes first. If A06 fails, stop that candidate's behavioral certification immediately.
- Codex G6 requires installation/resolver plus fresh A01/A03/A09/A10/A12.
- ChatGPT Project is non-blocking for v0.2.2 Preview unless release scope is explicitly changed through architecture review.
- Required-surface `PLATFORM_LIMITATION` is BLOCKED, never PASS.
- No historical A01–A06 result may fill a v0.2.2 case.
- No model behavior may be used to infer installed bytes.
- Compatibility matrix updates only from observed evidence.
- Generated plugin materialization is generated output, not handwritten production code; its correctness gate is deterministic rebuild + independent validator rather than a new handwritten-code TDD cycle.
- Marketplace registration is generated from tested renderer; it does not invent metadata manually.
- Merge, release/tag creation, marketplace publication beyond the tested M registration, branch deletion, and Stable promotion require separate explicit owner authorization.

## Review Focus

1. **Candidate drift between cases:** every A-case record must point to the same `candidate_tree_sha256` and target digest.
2. **Marketplace pin drift:** M must pin P exactly; P must validate against S.
3. **A06 fail:** no later ChatGPT A-case may be counted toward certification after the canary fails for that candidate.
4. **Host cannot prove install identity:** certification blocks rather than inferring candidate bytes from behavior.
5. **Required Codex limitation:** if resolver/install or required subset cannot be exercised, G6 remains blocked and Preview cannot be certified under the current profile.
